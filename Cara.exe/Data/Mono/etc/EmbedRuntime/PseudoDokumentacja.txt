1. Dyrektywy #pragma comment
Cel i działanie:
#pragma comment(lib, "nazwa_biblioteki") – automatycznie linkuje biblioteki (.lib) do projektu podczas kompilacji.

Przykłady w kodzie:

cpp
#pragma comment(lib, "winmm.lib")  // Biblioteka multimedialna (odtwarzanie MP3)
#pragma comment(lib, "kernel32.lib") // API systemowe (procesy, pamięć)
#pragma comment(lib, "user32.lib")   // GUI (okna, komunikaty)
Dlaczego to użyto?
Uniknięcie ręcznej konfiguracji w IDE – kompilator sam dodaje biblioteki do pliku wykonywalnego.

Manifest zależności:
cpp
#pragma comment(linker, "/manifestdependency:...")
Określa wersję Common Controls (wizualne elementy Windows).

Zapobiega "przyciemnieniu" GUI w nowszych systemach (np. Windows 10/11).

2. APIENTRY WinMain vs int main()
Różnice architektoniczne:
int main() – standardowy punkt wejścia dla aplikacji konsolowych.

WinMain – entry point dla aplikacji Windows API (GUI), nawet jeśli używa konsoli.

cpp
int APIENTRY WinMain(
  HINSTANCE hInstance,      // Handle instancji aplikacji
  HINSTANCE hPrevInstance,  // Przestarzałe (zawsze NULL)
  LPSTR lpCmdLine,          // Argumenty wiersza poleceń
  int nCmdShow)             // Tryb wyświetlania okna
APIENTRY – makro definiujące konwencję wywołania jako __stdcall (wymagane przez WinAPI).

Dlaczego WinMain?
Aplikacja domyślnie nie ma konsoli (to GUI app), ale AllocConsole() tworzy ją dynamicznie.

Umożliwia dostęp do pełni WinAPI (np. komunikaty MessageBox, zarządzanie procesami).
